## ✏️ Как отредактировать текст

Откройте нужный файл в папке `_sections/` и правьте обычный текст. Например,
заголовок первого экрана — `_sections/02-hero.md`:

```markdown
---
title: Юридическая помощь юридическим лицам и предпринимателям
---

Текст блока.
```

Это обычный Markdown:

```markdown
### Заголовок подраздела

Абзац текста.

- Пункт списка
{: .grid}
```

**Что означают сокращения:**

* `##` — заголовок второго уровня
* `###` — заголовок третьего уровня (подраздел)
* `-` — список
* `1.` — нумерованный список
* `**жирный**` — выделение
* `[текст](ссылка)` — ссылка

### 🏷️ Метки оформления

Строка `{: ...}` ставится **сразу под** блоком, с новой строки. Это метка kramdown.

```
- Пункт списка
- Ещё пункт
{: .grid}
```

**Класс** — отвечает за внешний вид:

| Что нужно | Как написано | Класс |
|---|---|---|
| Сетка в 2 колонки | список + `{: .grid}` | `.grid` |
| Принципы со значками-иконками | список + `{: .grid .grid--icons}` | `.grid--icons` |
| Направления карточками с зелёными галочками | список + `{: .grid .grid--dirs}` | `.grid--dirs` |
| Услуги плитками | нумерованный список + `{: .cards .cards--numbered .cards--tiles}` | `.cards--tiles` |
| Категории дел списком | список + `{: .cards}` | `.cards` |
| Шаги с крупными цифрами (порядок работы) | нумерованный список + `{: .steps}` | `.steps` |
| Квалификация (диплом, ИНН) | список + `{: .facts}` | `.facts` |
| Преимущества (главный блок) | список + `{: .hero__facts}` | `.hero__facts` |
| Вопросы и ответы (аккордеон) | список + `{: .faq}` | `.faq` |
| Контакты | список + `{: .contacts}` | `.contacts` |
| Врезка-предупреждение | цитата `> ...` + `{: .notice}` | `.notice` |
| Юридическая оговорка мелким шрифтом | текст + `{: .disclaimer}` | `.disclaimer` |
| Кнопка | `[Текст](#contacts){: .btn .btn--primary}` | `.btn` |

Если убрать метку — текст останется обычным, ничего не сломается.

### 🧱 Шапка блока (вводные данные файла)

У каждого файла в `_sections/` в самом начале, между `---`, указано, как блок
выглядит. Это не текст сайта, а настройки блока:

```yaml
---
order: 5                          # порядок блоков, по возрастанию
anchor: services                  # якорь для меню и подвала
eyebrow: Услуги                   # мелкая надпись над заголовком
title: Что входит в работу        # сам заголовок блока
heading: h1                       # h1 только у блока hero, по умолчанию h2
modifier: section--alt            # серый фон
photo: /assets/img/photo.jpg      # фото, необязательно
lead: Абзац под заголовком         # вступление, необязательно
---
```

| Поле | Что делает | Убрать можно |
|---|---|---|
| `order` | Ставит блок в нужное место на странице | Нет |
| `anchor` | Ссылка вида `zakon-no.github.io/#services` | Да |
| `eyebrow` | Надпись мелким шрифтом над заголовком | Да |
| `title` | Заголовок блока | Да |
| `heading` | Уровень заголовка: `h1` или `h2` | Да |
| `modifier` | Фон блока | Да |
| `photo` | Фотография слева от текста | Да |
| `lead` | Абзац-вступление под заголовком | Да |

# 💻 Как запустить сайт локально

Это нужно, чтобы видеть изменения **до** публикации: правите файл — страница
обновляется сама.

## 1️⃣ Проверьте версию Ruby

```bash
ruby -v
```

✅ Хорошо — `ruby 3.x` или новее.
❌ Плохо — `ruby 2.6.10` (это системный Ruby от macOS, он **старый и заблокирован**).

Если версия 2.6, поставьте нормальный:

```bash
brew install ruby
```

## 2️⃣ Сделайте так, чтобы команды находили нужный Ruby

**Почему это нужно.** В macOS есть два Ruby:

| | Системный | Тот, что нужен |
|---|---|---|
| Где | `/usr/bin/ruby` | `/opt/homebrew/bin/ruby` |
| Версия | 2.6.10 | 4.0.7 |
| Запись папок | 🔒 заблокирована macOS | ✅ можно ставить программы |

В системный Ruby программы ставить нельзя — папка защищена самой системой (SIP).
Поэтому Homebrew должен стоять в PATH **раньше** `/usr/bin`.

Выполните **один раз** — скопируйте эти 2 строки в файл `~/.zshrc`:

```bash
echo '
# ── Homebrew и Jekyll ──
export PATH="/opt/homebrew/bin:/opt/homebrew/sbin:$PATH"
export PATH="$(ruby -r rubygems -e '"'"'print Gem.bindir'"'"'):$PATH"
' >> ~/.zshrc
```

> 💡 **Что делает вторая строка.** Команды, установленные через `gem` (например
> `jekyll`), лежат в папке `/opt/homebrew/lib/ruby/gems/4.0.0/bin` — обратите
> внимание, в имени есть номер версии Ruby. Чтобы после обновления Ruby путь не
> сломался, мы не пишем его руками, а вычисляем автоматически командой
> `ruby -r rubygems -e 'print Gem.bindir'`.

Закройте терминал и откройте заново. Проверьте:

```bash
ruby -v      # должно быть 3.x или новее, НЕ 2.6
jekyll -v    # должна показать версию Jekyll
```

## 3️⃣ Установите программы для проекта

```bash
cd "/Users/alexandrfilin/Documents/Work/1. Юрист/www/Сайт-визитка"
bundle install
```

Команда читает файл `Gemfile` и ставит всё, что нужно. Занимает 1–3 минуты
при первом запуске.

## 4️⃣ Запустите сайт

```bash
bundle exec jekyll serve
```

Через пару секунд в терминале появится:

```
Server running... Press ctrl-c to stop.
```

Откройте в браузере:

👉 **http://localhost:4000/**

### 🎁 Что умеет `serve`

| Что делаете | Что происходит |
|---|---|
| Сохранили файл в VS Code | Страница обновляется сама через 1–2 секунды |
| В браузере нажали `Cmd + Shift + R` | Видите результат без кэша |
| Нажали `Ctrl + C` в терминале | Сервер остановился |

Отдельная команда, которая **не** запускает сервер, а просто собирает сайт в папку
`_site` (248 КБ) — пригодится, чтобы проверить, всё ли собралось:

```bash
bundle exec jekyll build
```

## 5️⃣ Если что-то пошло не так

| Ошибка | Причина | Что сделать |
|---|---|---|
| `You don't have write permissions for the /Library/Ruby/Gems/2.6.0 directory` | Команда `gem` попала в системный Ruby 2.6 | Сделайте шаг 2, затем откройте терминал заново |
| `zsh: command not found: jekyll` | Jekyll установлен, но его папка не в PATH | Сделайте шаг 2, затем `gem install jekyll` |
| `ruby -v` показывает 2.6.10 | Homebrew в конце PATH | Сделайте шаг 2 |
| `Could not find gem 'jekyll'` | Не выполнен `bundle install` | Выполните шаг 3 |
| Порт 4000 занят | Уже запущен другой Jekyll | `bundle exec jekyll serve --port 4001` |
| Страница открывается, но старая | Браузер показывает кэш | Нажмите `Cmd + Shift + R` |
| `Permission denied` при `bundle install` | Файлы проекта принадлежат другому пользователю | Остановите работу и обратитесь |

> 🔎 **Проверить, какой Ruby используется прямо сейчас:**
> ```bash
> which ruby
> ruby -v
> ```
> Первый ответ — путь к Ruby, второй — версия. Это самая полезная команда при
> любой проблеме с установкой.

## ⚙️ 5. Как Jekyll превращает текст в сайт

Пошагово, на примере одной строки:

**Шаг 1.** Вы пишете в `_sections/05-services.md`:

```markdown
---
title: Что входит в работу
anchor: services
---

1. **Правовой анализ документов**
{: .cards .cards--numbered}
```

**Шаг 2.** Jekyll читает файл и находит первые строки между `---`:

```yaml
---
layout: default
title: "Филин А.С. — юрист..."
---
```

Поле `layout: default` означает: «оберни содержимое в `_layouts/default.html`».

**Шаг 3.** Метка превращается в HTML:

```html
<h2 id="services">Что входит в работу</h2>
```

**Шаг 4.** Всё содержимое вставляется в каркас вместо `{{ content }}`:

```html
<main id="main" class="container">
  <h2 id="services">Что входит в работу</h2>
  ...
</main>
```

**Шаг 5.** Результат записывается в `_site/index.html`.

> 💡 Именно поэтому нельзя писать HTML руками в `.md` — Jekyll ожидает Markdown,
> и сам HTML будет экранирован. Исключение — оформление, которое Markdown не умеет:
> для него и сделаны метки `{: .grid}`.

## 🧩 7. Файл Gemfile — зачем он

```ruby
source "https://rubygems.org"
gem "jekyll", "~> 4.4"
gem "webrick", "~> 1.9"
```

| Строка | Значение |
|---|---|
| `source` | откуда скачивать программы |
| `gem "jekyll", "~> 4.4"` | Jekyll версии 4.4.x (знак `~>` = «совместимые версии») |
| `gem "webrick"` | маленький сервер для `serve`; в новом Ruby убран из стандартных |

Без `Gemfile` каждый ставил бы Jekyll случайной версии, и у одного человека сайт
собирался бы, а у другого — нет. `Gemfile` фиксирует версию для всех одинаково.

### Что происходит после `git push`

```
1️⃣  вы          git push
2️⃣  →           файлы уезжают на GitHub
3️⃣  GitHub      запускает Jekyll сам
4️⃣  GitHub      получает готовые HTML
5️⃣  →           отдаёт их посетителям
```

⏱️ 60–120 секунд. Скорость зависит от загрузки серверов GitHub, не от вас.

### Как проверить, что сайт собрался

```bash
gh run list --limit 3        # последние сборки
gh run watch                 # смотреть текущую сборку
gh run view <номер> --log-failed   # ошибки, если сборка упала
```

Если сборка упала, **на сайте ничего не пропадёт** — останется предыдущая
рабочая версия. Простоя не будет.

`main`, режим — сборка Jekyll. GitHub делает это автоматически для репозиториев
с таким именем.

## 🆘 11. Решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| `write permissions for /Library/Ruby/Gems/2.6.0` | `gem` бьёт в системный Ruby 2.6 | Настроить PATH: раздел «Как запустить локально», шаг 2 |
| `command not found: jekyll` | папка с gem-командами не в PATH | То же + `gem install jekyll` |
| `ruby -v` = 2.6.10 | Homebrew в конце PATH | То же |
| `Could not find gem` | не выполнен `bundle install` | Выполнить |
| Порт 4000 занят | уже запущен Jekyll | `bundle exec jekyll serve --port 4001` |
| На странице старое | кэш браузера | `Cmd + Shift + R` |
| Изменения не видны | сервер не перезапускается | `Ctrl + C`, затем `bundle exec jekyll serve` |
| На сайте старое | сборка ещё идёт | подождать 2 минуты, `gh run watch` |
| На сайте 404 | неверный адрес страницы | проверить `permalink` и адрес в `_config.yml` |
| Сайт не открылся вообще | упала сборка | `gh run view <номер> --log-failed` |

## 🔀 Смена адреса

Адрес задаётся в `_config.yml`:

```yaml
url: "https://zakon-no.github.io"
baseurl: ""
```

| Ситуация | Что сделать |
|---|---|
| Свой домен `afilin.ru` | `url: "https://afilin.ru"`, `baseurl: ""`, добавить файл `CNAME` с именем домена |
| Перенос в организацию `afilin-law` | `baseurl: "/afilin-law"`, репозиторий переименовать |
| Оставить как есть | ничего не менять |

Не забудьте поправить `robots.txt` и `sitemap.xml` — они не собираются
автоматически, в отличие от тегов `canonical` и `og:url`.

**Почему не `afilin.github.io`:** логин `afilin` на GitHub занят посторонним
аккаунтом с 2013 года, а имена пользователей и организаций занимают одно
пространство — поэтому и логин, и организация `afilin` недоступны. Сайт лежит на
логине `zakon-no`, который принадлежит вам.

Формы на сайте нет: заявки принимаются по телефону и по электронной почте. Кнопка

браузера, форму можно подключить через Formspree или Netlify Forms.
