## 1. Устройство

Статический сайт без фреймворков. Сборка — один скрипт на Python.

```
index.md      весь текст сайта в одном файле — редактируется только он
build.py      сборщик: index.md → index.html, offer.md → offer.html
serve.py      локальный сервер: отдаёт сайт и следит за index.md
index.html    готовый сайт, отправляется в интернет
offer.md      текст отказа от оферты
offer.html    готовая страница оферты
assets/css/styles.css    стили
assets/js/main.js         мобильное меню и аккордеон
assets/img/               фотография и монограмма
.vscode/tasks.json        кнопки в VS Code, сервер запускается сам
```

**Правило:** текст правится только в `index.md` и `offer.md`, никогда в
`index.html` и `offer.html` — они перезаписываются сборкой. В начало каждого
собранного файла вставляется пометка об этом, чтобы правка руками была
заметна сразу.

`.nojekyll` — чтобы GitHub Pages отдавал страницы как есть, без обработки.

### Сборка, сервер и проверка

Владелец правит `index.md` в VS Code. Задача «Сайт: локальный сервер»
поднимает `serve.py`, который:

- отдаёт сайт на `http://localhost:8080/` и слушает только `127.0.0.1`;
- пересобирает страницы сам, когда изменены `index.md`, `offer.md`, `build.py`;
- при запуске сверяет даты исходников и готовых файлов и достраивает отставшее;
- добавляет в отдаваемые страницы скрипт автообновления, чтобы браузер
  перезагрузился сам. На диск этот скрипт не попадает — в интернет уходит
  чистый файл;
- запрещает кэширование ответов (`Cache-Control: no-store`), иначе браузер
  показывал бы старый `index.html`.

Задача запускается при открытии папки (`runOn: folderOpen`), разрешение
задано `task.allowAutomaticTasks` в `.vscode/settings.json`. Владельцу не
нужны команды в Терминале.

Если требуется разовая сборка:

```bash
python3 build.py
```

Ничего устанавливать не нужно: только стандартная библиотека Python. Код
должен оставаться совместимым с Python 3.9 (`/usr/bin/python3`) и 3.12 —
VS Code может выбрать любой из них.

Разовый сервер для проверки изменений: `python3 -m http.server 8080`.
Скрипты и сборщик запускать в фоне нельзя: если процесс завершится, страница
перестанет собираться, и владелец не заметит.


## 2. Формат `index.md`

Между строками `---` в начале файла — настройки страницы: `title`,
`description`, `name`, `role`, `phone`, `phone_link`, `email`, `city`.

Дальше девять разделов, каждый начинается со строки `## Заголовок`:

```
## Заголовок раздела

*мелкая надпись над заголовком*

Первый абзац — вступление, выделяется крупнее.

Остальной текст, списки и подзаголовки.
```

- Разделов девять, порядок задан владельцем, менять без согласования нельзя:
  первый экран → о юристе → принципы → направления → услуги → порядок работы →
  категории дел → вопросы → контакты.
- Порядок определяет оформление: фон блока, фотографию, классы списков и
  заголовки меню. Всё это задано в `SECTIONS` в начале `build.py`.
- Текст настройки разделов в `index.md` не пишется — он в `build.py`.
- Меню, кнопки, фотография и подпись подвала собираются автоматически.

Поддерживаемая разметка: `###` подзаголовок, `-` список, `1.` нумерованный
список, `**жирный**`, `*курсив*`, `[текст](ссылка)`, `> врезка`. Больше ничего
не требуется; не добавляй HTML в `index.md`.

## 3. Стиль

Сайт должен вызывать доверие и транслировать статус, опыт и надёжность.

**Запрещено:**
- оценочные маркетинговые приёмы: «лучший», «№1», «первый», «уникальный»,
  «гарантируем результат», «100%», «быстро и качечно», «эксперт №»;
- юридически недопустимые обещания результата по конкретным делам;
- эмодзи, восклицательные знаки в заголовках, «кричащие» формулировки;
- анимация: только `transition` на hover и плавный скролл;
- тени-«жировки», скругления больше 4 px, градиенты, декоративные иллюстрации;
- Google Fonts и любые внешние запросы: шрифты только системные.

**Обязательно:**
- заголовки `var(--font-head)`, вес 400, без жирного;
- линии 1 px `var(--line)`, акценты только `var(--accent)` и `var(--ok)`;
- ровно один `h1` — на первом экране.

**Палитра (не менять без согласования):**

| Токен | Значение |
|---|---|
| `--bg` | `#ffffff` |
| `--bg-alt` | `#f6f7f9` |
| `--bg-deep` | `#14263b` |
| `--text` | `#1b1f24` |
| `--text-muted` | `#5a626b` |
| `--accent` | `#1c3a5e` |
| `--line` | `#e3e6ea` |
| `--ok` | `#2e7d5b` |

**Высота изображений:** у `<img>` обязателен `height: auto` в CSS. Иначе
HTML-атрибут `height` превращается в подсказку, ширина переопределяется
правилом, а высота нет — и фото растягивается. Так уже ломалось.

## 5. Юридические формулировки

Сайт **не является публичной офертой** — оговорка обязательна в подвале и в
разделе «Контакты». Сайт не является рекламой. Категории дел сопровождаются
оговоркой об отсутствии прогнозов и гарантий результата.

Страницы «Политика конфиденциальности» нет. Позиция владельца: сайт ничего не
принимает и никого не регистрирует, а только сообщает адрес почты — человек сам
пишет письмо со своего адреса. Персональные данные не собираются.
**Не предлагать вернуть её без новой прямой просьбы.**

`offer.md` сохранён и работает как `/offer.html`, но ссылка на него в подвале
отключена по решению владельца. Текст типовой и требует проверки юристом.
Ссылку вернуть можно в `build.py`, в блоке `page()`.

Мессенджеры (Telegram, WhatsApp) с сайта удалены по решению владельца. Не
возвращай и не упоминай без прямой просьбы.

Формы обратной связи нет и не нужна: приём заявок идёт по телефону и почте,
кнопка «Написать» открывает `mailto:`. Цен нет. Отзывов и кейсов с исходами нет.

## 7. Перед завершением правки

1. `python3 build.py` — сборка проходит без ошибок и без предупреждения о
   количестве разделов.
2. Проверь собранный `index.html`: девять блоков, одна `h1`, нет дублей `id`,
   нет битых якорей, ссылки на `assets/` существуют, абсолютных путей нет.
3. Убедись, что сгенерированный файл начинается с пометки о сборке и **не**
   содержит `/__generated` — этот скрипт добавляется только `serve.py` при
   локальном просмотре.
4. Сравни текст с прежней версией, чтобы ничего не пропало и не задвоилось.
5. Коммит и пуш — **только по прямой просьбе владельца**.

Публикация всегда одной отправкой: `.nojekyll`, `index.html`, `offer.html`,
`assets/`, `build.py`, `serve.py`, `.vscode/` и удаление файлов Jekyll должны
попасть в один коммит. Если разорвать это на части, GitHub Pages временно
отдаст сломанный сайт.
