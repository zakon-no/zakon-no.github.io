## 1. Стек и структура

Статика без сборщика. Никаких фреймворков, сборщиков, npm-зависимостей и внешних
CDN. GitHub Pages отдаёт файлы как есть.

```
index.html          главная страница, одностраничный лендинг
privacy.html        политика конфиденциальности
offer.html          отказ от юридической оферты
content/*.md        исходники текстов юридических документов
assets/css/styles.css   все стили
assets/js/main.js       мобильное меню, активный пункт меню, год в подвале
assets/img/photo.jpg    фотография (877×1100)
assets/img/favicon.svg  монограмма «АФ»
```

Правки вносятся в `index.html` и `assets/css/styles.css`. Разметка и стили лежат
в одном файле каждый — не создавай новых CSS-файлов и не дроби HTML на компоненты.

Шрифты только системные: `Georgia, "Times New Roman", serif` для заголовков,
`-apple-system, "Segoe UI", Arial, sans-serif` для текста. Google Fonts и любые
внешние запросы запрещены.

## 2. Стиль — главное требование

Сайт должен вызывать доверие и транслировать статус, опыт и надёжность.

**Запрещено:**
- оценочные маркетинговые приёмы: «лучший», «№1», «первый», «уникальный»,
  «гарантируем результат», «100%», «быстро и качественно», «эксперт №»;
- юридически недопустимые обещания результата по конкретным делам;
- эмодзи, восклицательные знаки в заголовках, «кричащие» формулировки;
- анимация: допустимы только `transition` на hover и плавный скролл.
  Никаких параллаксов, счётчиков, карусель, анимации появления;
- тени-«жировки», скругления больше 4 px, градиенты, декоративные иллюстрации.

**Обязательно:**
- сдержанная типографика: заголовки `var(--font-head)`, вес 400, без жирного;
- тонкие линии 1 px (`var(--line)`), цветовые акценты только `var(--accent)`;
- ссылка «через подчёркивание» не делается, но интерактивные элементы — да.

**Палитра (не менять без согласования):**

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#ffffff` | фон |
| `--bg-alt` | `#f6f7f9` | секции через одну, карточки |
| `--bg-deep` | `#14263b` | подвал |
| `--text` | `#1b1f24` | основной текст |
| `--text-muted` | `#5a626b` | вторичный текст |
| `--accent` | `#1c3a5e` | акцент, ссылки, номера |
| `--line` | `#e3e6ea` | разделители |

## 3. Факты — не выдумывать

Разрешено использовать только то, что передано владельцем или есть в исходниках
(`Контент.docx`, `Договор оказания юридических услуг_шаблон.doc`).

**Подтверждённые факты:**
- опыт по юридической профессии — **более 25 лет** (цифра «17 лет» из исходника
  не используется, владелец выбрал 25; не возвращать 17);
- город работы — Белгород;
- высшее юридическое образование;
- работа дистанционно; выезды в другие регионы по согласованию;
- территория оказания услуг: г. Белгород и до 3 км от границы города;
- рабочее время: пн–пт, 8:30–18:30;
- стоимость определяется до начала работ, публикуется только «по запросу»;
- услуги оказываются на основании договора оказания юридических услуг.

**Запрещено:** выдумывать награды, стаж в конкретных организациях, вузы, кейсы с
конкретными исходами, отзывы клиентов, названия компаний-клиентов, проценты
выигранных дел, любые оценки качества услуг.

## 4. Юридические формулировки

Сайт **не является публичной офертой** — оговорка обязательна в подвале
(`.footer__disclaimer`) и в блоке контактов. Сайт не является рекламой.

Категории дел сопровождаются оговоркой об отсутствии прогнозов и гарантий
результата (`.disclaimer` в секции `#practice`).

## 5. Заглушки — их нельзя оставлять незаметными

В коде есть заглушки контактов. Перед любым ответственным коммитом проверяй:

```bash
grep -n "___" index.html privacy.html offer.html
```

Заменить нужно: телефон (`+7 (___) ___-__`, `tel:+7_______`), e-mail
(`you@example.com`), Telegram (`https://t.me/______`), WhatsApp
(`https://wa.me/7__________`), ИНН и ОГРНИП в `.footer__requisites`.
Не заменяй их выдуманными правдоподобными данными — только реальными от владельца.

## 6. Структура главной страницы

Порядок секций менять нельзя без согласования с владельцем:

`header` → `#about` (О юристе) → `#directions` (Направления) → `#services`
(Услуги) → `#process` (Порядок работы) → `#practice` (Категории дел) →
`#faq` (Вопросы) → `#contacts` (Контакты) → `footer`

- `header` — монограмма «АФ», «Филин А.С. — юрист», слоган
  «Юридическая помощь бизнесу и гражданам», телефон, кнопка «Написать»;
- `hero` — H1, слоган, 2–3 преимущества, кнопки «Получить консультацию» и «Услуги»;
- ровно один `h1` на страницу, далее `h2` → `h3`, без пропусков уровней.

## 7. Чего на сайте нет — и это не баг

- **Формы обратной связи нет.** Владелец отказался от неё. Приём заявок идёт
  по телефону, в мессенджерах и через `mailto:`. Если владелец не попросит
  вернуть форму — не добавляй её. Учти: в `privacy.html` пункты 2 и 3 пока
  описывают сбор персональных данных «через форму обратной связи»; если форма
  не появится, этот текст нужно переписать под приём обращений по e-mail и
  в мессенджерах.
- **Цен нет.** Только формулировка «определяется до начала работ».
- **Отзывов и кейсов с исходами нет.** Есть только обезличенные категории дел.
- **Юридические тексты** лежат в HTML-страницах `privacy.html` и `offer.html`,
  их исходники — в `content/*.md`. Владелец пока не просил полные редакции;
  тексты типовые и требуют проверки перед публикацией.

## 8. Домен

Пока не привязан собственный домен, адрес — `https://zakon-no.github.io/afilin/`.
Он указан в `canonical` и `og:url` (`index.html`), в `canonical` юридических
страниц, в `robots.txt` и `sitemap.xml`. При переходе на свой домен заменить во
всех пяти местах и добавить файл `CNAME` в корень репозитория.

## 9. Перед завершением правки

1. Проверь разметку и ссылки — локальный сервер: `python3 -m http.server 8000`
   и открыть http://localhost:8000.
2. Пройди секции на ширинах 1200, 960, 620 px — переполнений быть не должно,
   бургер появляется на 1200 px и ниже.
3. Проверь, что `grep -n "___" index.html privacy.html offer.html` не показывает
   новых заглушек, если реальные контакты уже получены.
4. Коммит делай только по прямой просьбе владельца.
