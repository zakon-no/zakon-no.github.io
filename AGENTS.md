## 1. Стек и структура

Jekyll. GitHub Pages собирает сайт сам при каждом пуше — локально ничего
устанавливать не нужно. Никаких npm-зависимостей, плагинов и внешних CDN.
Файл `.nojekyll` удалён: без него Jekyll не запустится.

```
index.md            ВЕСЬ текст главной страницы
privacy.md          политика конфиденциальности
offer.md            отказ от юридической оферты
_layouts/default.html   каркас сайта: <head>, шапка, подвал
_config.yml         настройки сайта: url, baseurl, исключения
assets/css/styles.css   все стили
assets/js/main.js       мобильное меню, активный пункт меню, год в подвале
assets/img/photo.jpg    фотография (877×1100)
assets/img/favicon.svg  монограмма «АФ»
```

Три файла `.md` — это весь сайт. Папки `_includes` больше нет.

**Главное правило: текст правится в `index.md`, `privacy.md`, `offer.md`,
никогда не в собранном HTML.** Это обычный Markdown: `##` — заголовок,
`-` — список, `**жирный**` — выделение.

Оформление задаётся метками kramdown на отдельной строке сразу под блоком:

```
## Заголовок раздела
{: #services}

- Пункт
{: .grid}
```

Классы блоков: `.eyebrow`, `.lead`, `.section__lead`, `.photo`, `.grid`,
`.cards`, `.cards--numbered`, `.steps`, `.notice`, `.disclaimer`, `.btn`.
Если убрать метку — блок станет обычным текстом, ничего не сломается.

Классы `{: #якорь}` нужны для ссылок меню и подвала. Не переименовывай якоря
`#about`, `#principles`, `#directions`, `#services`, `#process`, `#practice`,
`#faq`, `#contacts` без согласования.

`auto_ids: false` в `_config.yml` — чтобы kramdown не плодил кириллические
`id` вида `#юридическим-лицам`.

Стили — только в `assets/css/styles.css`. Не создавай новых CSS-файлов.

Шрифты только системные: `Georgia, "Times New Roman", serif` для заголовков,
`-apple-system, "Segoe UI", Arial, sans-serif` для текста. Google Fonts и любые
внешние запросы запрещены.

Правку проверяй так: собрать локально нельзя (Ruby 2.6 в системе слишком старый),
поэтому после `git push` смотри лог сборки — `gh run list --workflow pages`,
`gh run view <номер> --log-failed`.

## 2. Стиль — главное требование

Сайт должен вызывать доверие и транслировать статус, опыт и надёжность.

**Запрещено:**
- оценочные маркетинговые приёмы: «лучший», «№1», «первый», «уникальный»,
  «гарантируем результат», «100%», «быстро и качественно», «эксперт №»;
- юридически недопустимые обещания результата по конкретным делам;
- эмодзи, восклицательные знаки в заголовках, «кричащие» формулировки;
- анимация: допустимы только `transition` на hover и плавный скролл.
  Никаких параллаксов, счётчиков, карусель, анимации появления;
- тени-«жировки», скругления больше 4 px, градиенты, декоративные иллюстрации.

**Обязательно:**
- сдержанная типографика: заголовки `var(--font-head)`, вес 400, без жирного;
- тонкие линии 1 px (`var(--line)`), цветовые акценты только `var(--accent)`;
- ссылка «через подчёркивание» не делается, но интерактивные элементы — да.

**Палитра (не менять без согласования):**

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#ffffff` | фон |
| `--bg-alt` | `#f6f7f9` | секции через одну, карточки |
| `--bg-deep` | `#14263b` | подвал |
| `--text` | `#1b1f24` | основной текст |
| `--text-muted` | `#5a626b` | вторичный текст |
| `--accent` | `#1c3a5e` | акцент, ссылки, номера |
| `--line` | `#e3e6ea` | разделители |

## 6. Структура главной страницы

Порядок секций задан владельцем, менять его без согласования нельзя:

`header` → `#about` (О юристе) → `hero` (заголовок и кнопки) →

`#practice` (Категории дел) → `#faq` (Вопросы) → `#contacts` (Контакты) → `footer`

- `hero.md` — H1, преимущества, кнопки «Получить консультацию» и «Услуги»;
- блок `#about` идёт ПЕРЕвым — по решению владельца, чтобы посетитель сразу видел юриста;
- `principles.md` — отдельная секция, в `#about` принципов быть не должно;
- ровно один `h1` на страницу, далее `h2` → `h3`, без пропусков уровней.
  `h1` находится в `hero.md`, то есть ниже `h2` из `#about` — это осознанное
  решение владельца, не считать ошибкой.

- **Отзывов и кейсов с исходами нет.** Есть только обезличенные категории дел.

  их исходники — в `content/*.md`. Владелец пока не просил полные редакции;

## 8. Адрес сайта

Адрес задаётся в `_config.yml`: `url` и `baseurl`. Теги `canonical` и `og:url`
собираются из них автоматически, дублировать руками не нужно. Отдельно правится
`robots.txt` и `sitemap.xml`.

Текущее состояние: `url: https://zakon-no.github.io`, `baseurl: ""`.
Репозиторий: `zakon-no/zakon-no.github.io`.

**Адрес `afilin.github.io` недостижим.** Логин `afilin` на GitHub занят
посторонним аккаунтом, созданным в 2013 году. Имена пользователей и организаций
занимают одно пространство, поэтому организацию с именем `afilin` создать нельзя.
Логин `filin` тоже занят посторонним аккаунтом.

Сайт перенесён на логин `zakon-no` — это собственность владельца:
`https://zakon-no.github.io/`.

Достижимые варианты дальше:
- собственный домен — рекомендуется, выглядит существенно статуснее;
- своя организация + одноимённый репозиторий: `afilin-law`, `afilinlegal`,
  `afilinlaw` — свободны, дадут адрес вида `https://afilin-law.github.io`.

При любом переходе: изменить `url`/`baseurl` в `_config.yml`, поправить
`robots.txt` и `sitemap.xml`, для домена добавить файл `CNAME`.
